# Contracts

### C-001: SCENE scene document (strict JSON)
Status: Frozen (revision 9)
Auth: None. Local file input, treated as untrusted: bounded size, no external entity expansion, no file or network access from a scene (NFR-021).
Request: Scene document per docs/Vectr/schema.md — id: string; projectId: string; name: string; formatVersion: string (^[0-9]+\.[0-9]+$, supported: 0.2); canvas: {width: number, height: number, background: string, a colour in any format SVG supports or `transparent`}; paletteId?: string; recipeId?: string; title?: string; description?: string; seed?: integer; a ProjectConfig document carries {id: string, name: string, formatVersion: string, defaultRecipeId?: string, defaultPaletteId?: string, defaultSceneId?: string, output: {format, width, height, density, background}}; a project's reusable definitions and its elements share one identifier namespace, so a definition id and an element id are unique across the project; a scene's `paletteId` is optional and falls back to the project's `defaultPaletteId`; elements: Element[]; a Definition document per docs/Vectr/schema.md — id: string; projectId: string; name: string; parameters: [{name: string, type: enum[number, string, boolean, token], default?: number|string|boolean|null}]; origin: {x: number, y: number}; its elements are its `elements` list of Element, each owned by it through `definitionId`; an IconSet document per docs/Vectr/schema.md — id: string; projectId: string; name: string; canvas: {width: number, height: number, background: string}; paletteId?: string; recipeId?: string; strokeProfileId: string; namePattern?: string (default `{name}`); icons: [{name: string, definitionRef: string, accessibleName?: string}]; Element (one shape for a scene and a definition) requires {id: string, order: integer, kind: enum[rect, ellipse, polygon, line, path, text, group, repeat, boolean, alongPath, offset, projection, procedural, raster, instance], geometry: object, transform: Transform, opacity: number 0..1, visible: boolean} and may carry {sceneId: string|null, definitionId: string|null, parentId: string|null, name: string, accessibleName: string, fill: Paint|null, stroke: Stroke|null, fontId: string|null, definitionRef: string|null, bindings: Binding[]|null}; exactly one of sceneId and definitionId is set; Binding = {name: string, value: number|string|boolean|ParamRef}; ParamRef = {param: string}; Paint = {kind: enum[token, gradient], ref: string}, where `ref` is a Palette token name when kind is `token` and a Gradient id when kind is `gradient`; Stroke = {profileId: string, paint: Paint}; a parameter-capable field — a numeric geometry, transform, or opacity field, `geometry.text` or `geometry.pathData`, `visible`, or a whole `fill` or `stroke.paint` — holds either a literal of the field's type or a parameter reference (ParamRef); a reference is valid only where the element is owned by a definition, names one of that definition's declared parameters, and matches the field's type; a text element's geometry carries {text: string, fontSize: number, align: enum[start, center, end], lineHeight: number, letterSpacing: number, width?: number} and is anchored by x, y at the first line's baseline; Transform requires {translateX: number, translateY: number, rotate: number, scaleX: number, scaleY: number} and may carry {skewX: number, skewY: number}; constraints?: Constraint[] (id: string, sceneId: string, kind: enum[equalSpacing, align, attach, contain, snapToGrid], elementIds: string[>=2], axis?: enum[x, y, both]|null, value?: number|null). Validation: exactly one of `sceneId` and `definitionId` is set; `definitionRef` and `bindings` apply only to an instance; a `definitionRef` that does not resolve, a reference cycle among definitions, a parameter reference in a scene element or naming a parameter the element's definition does not declare or whose type does not match its field, and a binding for a parameter the placed definition does not declare are errors; fill and stroke are independent — an element may carry either, both, or neither; a stroke is well-formed only when `profileId` and `paint` are both present (required within `stroke`); a text element requires `geometry.text` and `geometry.fontSize`; `fontId` may appear only on a text element; a text element may not be an operand of a boolean, offset, projection, repeat, or alongPath element. A paint `ref` is a name, not resolved at parse time; the compiler resolves it (C-002).
Response Ok: Parsed scene model; every element addressable by a stable identifier; the document round-trips without loss.
Errors: E_SCHEMA (unknown property, missing required field, or invalid value, with location), E_PARSE (not valid JSON or not a scene document), E_FORMAT_VERSION (unsupported formatVersion; names the version and the supported range), E_DUPLICATE_ID (duplicate element identifier), E_INVALID_COLOR (a canvas background that is not a colour in any format SVG supports and not `transparent`; names the field and its location), E_DUPLICATE_NAME (two elements share an accessible name; names the field and its location)

### C-002: CALL vectr-core library API
Status: Frozen (revision 10)
Auth: In-process caller; no authentication. Deterministic and safe for concurrent use with no shared mutable state (FEAT-021).
Request: parse(source: &str) -> Result<Scene, Diagnostics>; validate(&Scene) -> Diagnostics; parse_gradient(source: &str) -> Result<Gradient, Diagnostics>; validate_gradient(&Gradient) -> Diagnostics; parse_definition(source: &str) -> Result<Definition, Diagnostics>; validate_definition(&Definition) -> Diagnostics; compile(&Scene) -> Result<RenderModel, Diagnostics>; compile_with_style(&Scene, &StyleContext) -> Result<RenderModel, Diagnostics>; compile_definition(&Definition, &StyleContext) -> Result<RenderModel, Diagnostics>; compile_subtree(&Scene, element_id: &str, &StyleContext) -> Result<RenderModel, Diagnostics>; export_svg(&RenderModel, &SvgOptions) -> Result<String, Diagnostics>; export_svg_reporting(&RenderModel, &SvgOptions) -> Result<SvgExport, Diagnostics>; export_png(&RenderModel, &RasterOptions) -> Result<Vec<u8>, Diagnostics>; export_png_reporting(&RenderModel, &RasterOptions) -> Result<PngExport, Diagnostics>; resolve_fill(&Element, Option<&Palette>, &[Gradient], &mut Diagnostics) -> Option<Paint>; resolve_stroke(&Element, &[StrokeProfile], &mut Diagnostics) -> Option<ResolvedStroke>; resolve_stroke_paint(&Element, Option<&Palette>, &[Gradient], &mut Diagnostics) -> Option<Paint>; schema(form: Full|Compact) -> Result<String, Diagnostics>; schema_for(name: &str) -> Result<String, Diagnostics>; is_color(value: &str) -> bool; validate_color(&mut Diagnostics, value: &str, what: &str, path: impl Into<String>). SvgOptions {width?: number, height?: number, background?: string}; RasterOptions {width?: number, height?: number, density?: number, background?: string}. The reporting variants return the output alongside the exporter's warnings, which the plain variants cannot carry on success (C-003). `compile` runs without style assets and carries the scene's declared style references; `compile_with_style` resolves them against the caller's palette, stroke profiles, gradients and font assets (D-013). The compile context also carries the project's reusable definitions, so an instance element resolves without filesystem access; a definition that does not resolve, a reference cycle among definitions, and a parameter reference or binding that does not match the placed definition are located errors (FEAT-030). `compile_definition` and `compile_subtree` compile one part alone — a definition or a named element subtree — into a render model for part-scoped rendering (FEAT-031); an isolated definition resolves its colours and style from the project's default palette and default recipe, an isolated element subtree from its owning scene, and a part identifier resolves to a definition first and otherwise to the element subtree, in the project's shared identifier namespace. A part preview carries the part's name as the render model's `meta.title`, so it is not reported as a scene missing metadata (FEAT-026). A colour value — a palette token's value or a gradient stop's colour — is a colour in any format SVG supports (3-, 4-, 6-, and 8-digit hexadecimal; rgb() and rgba(); hsl() and hsla(); a named colour; or `transparent`), optionally carrying alpha, so a fill and a stroke carry independent transparency; a value that is not such a colour is a located error and no output is produced (FEAT-005, FEAT-018). `schema` and `schema_for` expose the published language contract (FEAT-017). StyleContext carries the caller's palette, stroke profiles, gradients and font assets — each font an id, a name and its bytes — so the compiler resolves every fill, stroke and font reference without filesystem access. A font asset with id `fallback` supplies the fallback font for glyphs the resolved font lacks (D-018). StyleContext also carries the scene's style recipe; when one is supplied, `compile_with_style` applies it — stroke-weight defaults, snapping, projection and depth ordering — so the same scene renders in the recipe's look (FEAT-007–FEAT-010). The library compiles and exports in process with no separate process, and its result for a given input matches the command line's, so an embedder and the CLI agree; concurrent calls are safe with no shared mutable state (FEAT-021). `export_pdf(&RenderModel, &PdfOptions) -> Result<Vec<u8>, Diagnostics>` and `export_pdf_reporting(&RenderModel, &PdfOptions) -> Result<PdfExport, Diagnostics>` emit vector PDF with text outlined, the page sized by the options (a default page size and a warning when none is given) and the named colour profile honoured; `PdfOptions {pageWidth?: number, pageHeight?: number, profile?: string, background?: string}` (FEAT-014). `parse_icon_set(source: &str) -> Result<IconSet, Diagnostics>`, `validate_icon_set(&IconSet) -> Diagnostics`, and `export_icon_set(&IconSet, &[Definition], &StyleContext, &ExportOptions) -> Result<Vec<IconExport>, Diagnostics>` parse, validate, and render a set's icons in process under the set's shared canvas, palette, recipe, and stroke profile, one output per icon named by the set's naming pattern (FEAT-025).
Response Ok: RenderModel, SVG text, or PNG bytes; identical input and seed yields byte-identical output (NFR-010).
Errors: Diagnostics — structured findings carrying severity (error|warning) and location (element id + JSON path); classes: invalid scene, unsupported feature, reference cycle, definition cycle, unresolved definition, invalid parameter binding, constraint conflict, defined size limit, missing rasterizer, missing font, missing palette token, missing stroke profile, missing gradient, invalid colour, unknown schema type

### C-003: MODEL render model (compiler to exporter seam)
Status: Frozen (revision 8)
Auth: Internal to vectr-core; read by every exporter (docs/Vectr/architecture.md, "Component: Compiler" and "Component: Export Layer").
Request: RenderModel { canvas: {width: number, height: number, background: string}, nodes: ResolvedNode[], meta: {title?: string, description?: string, recipe?: string, seed: integer}, diagnostics: Diagnostic[], fonts: ResolvedFont[] }; ResolvedNode = { id: string, name?: string, accessibleName?: string, order: integer, kind: string, groups: [{id: string, name?: string, accessibleName?: string}] (ancestor group chain, outermost first; empty for a root element), geometry?: resolved Shape (rect {x, y, width, height, rx, ry} | ellipse {cx, cy, rx, ry} | polygon {points} | line {points} | path {subpaths: [{segments, closed}]}; absent for a text node), text?: TextRun, transform: resolved Affine, paint: {fill?: Paint, stroke?: {paint: Paint, width: number, cap: string, join: string}}, opacity: number, visible: boolean }; Paint = {kind: "color", value: string} | {kind: "gradient", type: enum[linear, radial], stops: [{offset: number, color: string, opacity: number}] (two or more, ascending offset), spread: enum[pad, reflect, repeat], x1?: number, y1?: number, x2?: number, y2?: number, cx?: number, cy?: number, r?: number, fx?: number, fy?: number} — a linear gradient carries x1,y1,x2,y2 and a radial one carries cx,cy,r,fx,fy, all in object bounding-box units; TextRun = { value: string, fontId: string, fontSize: number, align: string, lineHeight: number, letterSpacing: number, width?: number }; ResolvedFont = { id: string, name: string, data: bytes (the font file, base64 in JSON) }. `fonts` carries every font a text node names, plus the caller's fallback asset (id `fallback`) when one is supplied (D-018). `nodes` is flat, in paint order; a group or composition is lowered to resolved nodes, and each node carries its ancestor group chain so an exporter can reconstruct the named-group nesting (FEAT-011, FEAT-012). A text node carries `text` and no `geometry`; its `fontId` names the resolved font in `fonts`, so an exporter finalizes glyph geometry with no external state (FEAT-011, FEAT-024). An `instance` element contributes no node of its own: it adds an entry (its id and name) to the ancestor chain of every node its definition resolves to, and its bindings are baked into those nodes' geometry and paint, so the model carries no unresolved definition reference (FEAT-030). `paint.fill` and `paint.stroke.paint` are fully resolved — a concrete palette colour, or a gradient whose stop colours are concrete palette colours and whose geometry is concrete; no unresolved colour or gradient reference survives compilation. `meta.recipe` names the recipe applied when the scene was compiled with one, and the recipe's effects are baked into the nodes' geometry, transform, paint and order. The model serializes to camelCase JSON (D-014). An `accessibleName` becomes the node's or group's SVG `<title>` while the maintenance `name` stays `data-name`, and a text element's string is carried as its accessible text; an export whose scene carries neither title nor description reports `W_MISSING_METADATA` (FEAT-026).
Response Ok: SVG text, PNG bytes, or PDF bytes whose appearance matches the render model.
Errors: none at this seam (compilation already succeeded); exporter findings are warnings: unsupported-feature (omitted with a warning), rasterizer-missing, font-missing, missing-glyph

### C-004: CLI vectr
Status: Frozen (revision 11)
Auth: None. Runs as the local user; no authentication and no network (docs/Vectr/architecture.md, "Cross-Cutting Concerns").
Request: vectr init [dir]; vectr validate [<scene>] [--json]; vectr compile [<scene>] [--out <file>] [--check]; vectr export [<scene>] --format svg|png|pdf [--out <file>] [--width <n>] [--height <n>] [--density <n>] [--background <color|transparent>] [--profile <srgb|cmyk>]; vectr inspect [<scene>] [--out <file>] [--width <n>] [--height <n>] [--density <n>] [--background <color|transparent>]; vectr schema [--type <name>] [--compact]; vectr render <part> [--out <file>] [--format svg|png] [--width <n>] [--height <n>] [--density <n>] [--background <color|transparent>]. `<scene>` is a scene identifier resolved among the project's scene documents; the project is found from the working directory. Omitting `<scene>` uses the project's `defaultSceneId`; a project that names no default is an error rather than a choice among its scenes. `<part>` is the identifier of a reusable definition or of a named element subtree, resolved in the project's shared identifier namespace (a definition first, otherwise the element subtree); it is rendered on its own, framed to its own bounds or to a requested size (FEAT-031). PDF export is gated by the `enable_pdf_export` flag (off by default) (FEAT-014); `inspect` renders a scene to a preview image for inspection, prints its path, and reports its size, with the preview size configurable (FEAT-022). `icon-set export [<set>] [--format svg|png|pdf] [--out-dir <dir>]` renders every icon in a set on its own under the set's shared canvas, palette, recipe, and stroke profile and exports each to a file named by the set's naming pattern; it is gated by the `enable_icon_set_mode` flag (off by default) (FEAT-025).
Response Exit 0: success; output written, or nothing written under --check. The schema command prints the published language contract (FEAT-017). `init` writes the project scaffold — configuration, the scene directory holding a starter scene the project names as its default, the default recipe, and a minimal authoring guide for coding agents at the project root, carrying orientation, the project's local facts, and a pointer to the schema rather than the full procedure; it writes no scene document at the project root (FEAT-016, FEAT-020).
Errors: Exit 1 (scene invalid; diagnostics printed), Exit 2 (usage error, missing/unreadable input, an unknown schema type listing similar type names, a scene identifier no document provides, a part identifier that resolves to no definition or element, or a project that names no default scene when none is given), Exit 3 (compilation failure: constraint conflict, cycle, defined size limit), Exit 4 (export dependency missing: rasterizer or font), Exit 5 (output I/O failure: unwritable path). Every non-zero exit prints a structured diagnostic with its location; no partial output is written and existing files are left untouched (NFR-011).

### C-005: MCP vectr-mcp server
Status: Frozen (revision 5)
Auth: Local. The server serves over stdio by default, with an opt-in loopback HTTP listener opened by an explicit bind flag; it widens filesystem scope only on explicit opt-in and makes no network calls unless configured (NFR-024).
Tools: validate (scene → diagnostics); compile (scene → render model); render (scene, format svg|png|pdf, width?, height?, density?, background? → the rendered output at the requested path; pdf is gated by enable_pdf_export, off by default); inspect (scene, format svg|png, width?, height?, density?, background? → the preview image's path, with the preview size configurable); render-part (part, format svg|png, width?, height?, density?, background? → the part's preview at the requested path, framed to the part's own bounds or to a requested size; `part` is the identifier of a reusable definition or a named element subtree, resolved in the project's shared identifier namespace (a definition first, otherwise the element subtree), FEAT-031); schema (full|compact|type:"<name>" → the language contract). Each tool publishes a discoverable JSON schema for its input and output; `tools/list` returns all of them with their schemas and `tools/call` invokes one with arguments matching its schema. The project's reusable definitions resolve for every scene a tool compiles, so an instance element expands without a separate argument (FEAT-030). A tool's scene is either a scene identifier resolved among a project's scenes — the project named by the caller, or the server's project context — or an inline scene document sent as a draft. Omitting both uses the project's `defaultSceneId`; a project that names no default is a structured error rather than a choice among its scenes, and a named scene overrides the default. An inline draft is not a project scene: it never becomes the default and never reads or writes it, and its assets resolve against the named project or the server's project context. A call naming both a scene identifier and an inline document is malformed.
Response Ok: the tool's structured result; `compile` returns the render model, `render` returns the written output's path, `validate` and `compile` return diagnostics alongside the result. Concurrent calls are safe with no shared mutable state (FEAT-021, FEAT-019).
Errors: a structured error (code, message, location) for an invalid scene, a scene identifier no document provides, a default that resolves to no document (naming it), a call naming both an identifier and an inline document, an unresolved asset reference in an inline draft, a part identifier that resolves to no definition or element, an unresolved definition or a reference cycle among definitions, or an unsupported capability; never a crash and never a partial file left behind (NFR-011).

### C-006: EVAL vectr-eval harness
Status: Frozen
Auth: Local and maintainer-run, gated by the `enable_eval_harness` flag (off by default; docs/Vectr/release.md). It calls a user-chosen authoring model provider with the user's credentials; Vectr itself makes no network call on behalf of a scene (NFR-024, NFR-026).
Request: vectr-eval run --corpus <dir> --model <provider:model> [--out <file>] — loads the versioned corpus, runs each prompt through the named authoring model and the toolchain, scores compile success and judged fidelity plus the hard-end sub-scores for depth and perspective, relative placement, parts joined at shared anchors, and subject accuracy, and writes a run record; vectr-eval compare <run-a> <run-b> — compares two runs of the same corpus and flags regressions. The corpus is versioned so comparisons stay meaningful; a prompt that cannot be scored is counted as a failure, never skipped.
Response Ok: A run record carrying the compile-success rate, the judged-fidelity score, the hard-end sub-scores, and the per-prompt results; a comparison naming the prompts that regressed.
Errors: Exit 1 (a run that cannot be scored, reported with its reason), Exit 2 (usage, an unreadable corpus, or a model that cannot be reached — reported failed with no partial results).
